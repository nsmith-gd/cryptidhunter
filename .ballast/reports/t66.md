STATUS: DONE
- Every run now has one world seed, so a hunt can be replayed exactly. Add `?seed=1234` to the address, or read the seed the game prints to the console. Cryptid behaviour, clue trails, where Bigfoot beds down and starts its trail, wood-knock timing, navigation choices and world dressing all draw from their own seeded stream, so one system rolling more dice never changes another. Only the tiny pitch/timing wobble in knock sounds is still truly random, since it doesn't affect the game.
- The game world now advances in fixed 1/60-second steps whatever the screen's frame rate. Movement, stamina, battery, the night clock, fear, cryptid AI and photo blur run identically at 30 or 144 fps. The camera and creatures are drawn smoothly between steps, and HUD and visual effects still update every frame. The catch grace period now runs on game time, not the wall clock.
- Verified (`npm run check:t66`, plus a unit test): the same seed and scripted inputs on two fresh loads gave identical state after 30 s (player, stamina, battery, Bigfoot's position and mood, all 38 clues); a different seed gave a different world; the same 10-second run drawn at 30 fps and at 144 fps ended bit-for-bit identical. Captures of both frame rates are in `.ballast/media/t66/`. The movement, flashlight, clue, cryptid, fear, camera, loadout, base camp and album checks still pass. The forest-pathing and dawn-bonus checks fail on main too and aren't caused by this.
- How to see it: `npm run dev`, play with `?seed=42`, reload, and the same world plays out the same way.
- Assumptions: 60 steps per second; after a long hitch the game skips at most 8 steps (≈0.13 s) rather than freezing to catch up. Tests can add `?simpaused` to drive the simulation themselves.
